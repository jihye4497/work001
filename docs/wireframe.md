# 오늘 뭐 담지? 와이어프레임

`docs/plan.md` 4절의 12개 화면을 같은 순서로 정의한다. 크기·색·상태 표시는 `style_guide.md`를 따른다. 상자 그림은 360px 휴대폰 기준이며 실제 글자 폭을 뜻하지 않는다. 계획서 밖의 배치·문구·기본 선택은 **(가정)**이다. 메뉴·수량 예시는 설계용이며 검수된 `Recipe`·`Ingredient` 값이 있을 때만 실제 화면에 표시한다. 새 화면·레시피 상세·결제·종료 전용 페이지를 추가하지 않는다.

## 0. 전체 흐름

```text
홈 → 기본 설정 → 재료 선택 ⇄ 메뉴 추천 ⇄ 장보기 목록
                    └─────────────────────┘ (양방향)
메뉴 추천 / 장보기 목록 → 선택 메뉴 클릭 → 인라인 조리 횟수 변경·삭제
모든 화면 → 기본 설정 → 저장 후 호출한 화면으로 복귀
홈(재방문) → 장보기 이어하기 → 재료 선택
장보기 목록 → 목록 복사·구매 체크 → 브라우저 종료 → 재방문 시 복원
장보기 목록 → 새 장보기 시작 → 같은 화면의 확인창
                              ├ 취소 → 현재 상태 유지
                              └ 확인 → ShoppingDraft 초기화 → 재료 선택
홈 / 푸터 → 장보기 가이드 → 오징어 활용 가이드
푸터 → 서비스 소개 / 문의 / 개인정보처리방침 / 이용 안내
잘못된 URL → 오류 페이지 → 홈 또는 재료 선택
```

결제 없음. 브라우저 종료는 별도 버튼 없이 가능하며 같은 브라우저·도메인에서 저장된 작업을 복원한다. 직접 URL 접근도 허용한다. 처음 설정하지 않고 핵심 화면에 온 경우 차단하지 않고 `기본 설정을 확인해 주세요.` 링크를 표시한다. 미설정 임시값은 기본 식사 인원 1명·기본 추천 방식 재료 최대 활용형 **(가정)**; 사용자가 저장하기 전 최초 설정 완료로 취급하지 않는다.

### 공통 배치·동작

- 모든 화면: 상단 64px 이상 로고 `오늘 뭐 담지?`(홈 링크) + `기본 설정` 링크, 다음 행 48px 이상 `재료 선택 | 메뉴 추천 | 장보기 목록` 3등분. 활성 링크에 3px #166534 밑줄과 aria-current. 이름이 길면 두 줄 허용. 헤더는 스크롤과 함께 이동한다.
- 본문 최대 1120px, 휴대폰 좌우 16px. 화면 제목은 본문 시작 24px 아래. 읽기 화면 본문 최대 720px. 상자 그림의 `공통 상단`은 위 두 행을 뜻한다.
- 모든 화면 바닥글: `장보기 가이드`, `서비스 소개`, `문의`, `개인정보처리방침`, `이용 안내` 링크. 16px 글자·각 클릭 영역 최소 48px·줄바꿈. `이 브라우저에 장보기 작업을 저장해요.` 안내. `공통 바닥글`은 이 영역을 뜻한다.
- `메뉴 추천`·`장보기 목록`: 제목 바로 아래 `기본 식사 인원: 1명 [기본 설정]`, `선택 메뉴` 제목과 줄바꿈 가능한 메뉴 버튼. 메뉴 버튼 클릭 시 그 아래 인라인 편집. `− [1회] + [삭제]`에서 −/+ 48×48px, 최솟값 1. 별도 인분 입력 없음. 편집 중에도 다른 메뉴·페이지 이동 가능. 변경 즉시 저장·추천/합산 갱신.
- 페이지 이동·추천 방식 변경·재료 추가/삭제는 `selectedRecipes`·`times`·구매 체크를 초기화하지 않는다. 기본 식사 인원 변경은 모든 메뉴에 적용한다. 동일 Recipe 중복 담기 금지.
- 저장 실패·손상 데이터 복구 안내는 제목 위 공통 알림 영역. 실제 복구 범위를 문구로 알리며 조용히 전체 초기화하지 않는다. 실패 후에도 현재 메모리 상태로 조작 가능. 데이터 읽기 실패는 관련 영역만 오류와 `다시 시도` 버튼을 표시한다.
- 정적 HTML 본문은 로딩 골격을 만들지 않는다. 상태 항목의 `해당 없음`은 불필요한 로딩·데이터 빈 상태를 만들지 않는다는 뜻이다.
- 광고는 승인 전 숨김·공백 0px. 승인 후 홈·메뉴 추천·장보기 목록·오징어 활용 가이드에 각각 최대 1개 **(가정)**. 장보기 가이드 목록에는 광고를 넣지 않는 해석 **(가정)**. `[광고]`는 승인 후 위치만 뜻한다. 본문과 32px, 클릭 요소와 48px 이상 이격한다. 더 보기·복사와 광고 사이도 48px 이상이다.

### 1. 홈 — `/` · `index.html`

- 목적: 서비스 용도를 이해하고 장보기를 시작하거나 이어간다.
- 배치:

```text
┌────────────────────────┐
│ 공통 상단               │
├────────────────────────┤
│ 오늘 뭐 담지?           │
│ 관심 식재료로 메뉴를 고르고│
│ 재료별 장보기 목록을 만들어요│
│ [기본 설정]             │
│ (재방문: [장보기 이어하기])│
│ 1 재료 선택             │
│ 2 메뉴 추천             │
│ 3 장보기 목록           │
│ [장보기 가이드]         │
│ [광고]                  │
│ 공통 바닥글             │
└────────────────────────┘
```

| 요소 | 내용(실제 문구 예시) | 누르면 일어나는 일 |
|---|---|---|
| 제목·설명 | `오늘 뭐 담지?`, `무료로 이용할 수 있어요.` | 없음 |
| 첫 방문 버튼 | `기본 설정` | 기본 설정으로 이동, 완료 후 재료 선택 |
| 재방문 버튼 | `장보기 이어하기` | 재료 선택으로 이동, 기존 작업 유지 |
| 단계 안내 | `재료 선택 → 메뉴 추천 → 장보기 목록` | 설명만 표시 |
| 콘텐츠 링크 | `장보기 가이드` | 장보기 가이드 이동 |

- 상태: 처음(데이터 없음)은 기본 설정 버튼. 불러오는 중은 정적 소개 유지·복원 영역만 `저장된 장보기를 확인하고 있어요.` 표시. 정상은 설정된 사용자에게 장보기 이어하기를 주 버튼으로 표시. 오류는 소개 유지·저장 복구/실패 알림 표시, 설정·핵심 화면 접근 허용.
- 광고 개수: 승인 전 0개 / 승인 후 하단 최대 1개.
- PC에서 달라지는 점: 소개·주 버튼과 3단계 설명을 1:1 두 열, 간격 32px. 광고는 두 열 아래 전체 폭.
- 연결된 plan.md 작업 번호: 1-2, 1-3, 2-3, 6-1, 6-2, 7-8.

### 2. 기본 설정 — `/settings.html`

- 목적: 기본 식사 인원과 기본 추천 방식을 저장한다.
- 배치:

```text
┌────────────────────────┐
│ 공통 상단               │
├────────────────────────┤
│ 기본 설정               │
│ 기본 식사 인원           │
│ [1명] [2명] [3명] [4명] │
│ 기본 추천 방식           │
│ ○ 재료 최대 활용형       │
│ ○ 추가 재료 최소형       │
│ ○ 여러 끼 식단형         │
│ ○ 세 가지 모두 비교      │
│ 오징어·팽이버섯·양파·감자 │
│ 선택한 방식 설명·예시    │
│ [저장하고 재료 선택]     │
│ 공통 바닥글             │
└────────────────────────┘
```

| 요소 | 내용(실제 문구 예시) | 누르면 일어나는 일 |
|---|---|---|
| 인원 라디오 | `기본 식사 인원`, `1명`~`4명` | UserSettings 임시 편집, 전체 메뉴에 적용할 인원 |
| 방식 라디오 | 세 추천 방식 + `세 가지 모두 비교` | 설명·예시 즉시 변경 |
| 예시 영역 | `재료 최대 활용형: 오징어·양파를 함께 쓰는 메뉴를 먼저 보여줘요.` | 없음; 추가 재료 최소형은 새 일반 재료 종류 수, 여러 끼 식단형은 조리 유형 다양성 설명 |
| 비교 설명 | `세 가지 모두 비교는 메뉴 추천에서 세 가지 탭을 전환하는 방식이에요.` | 없음; 세 목록 동시 표시 아님 |
| 저장 버튼 | 처음 `저장하고 재료 선택`, 수정 `저장하고 돌아가기` | UserSettings 저장; 최초 재료 선택, 수정은 호출한 내부 화면으로 복귀; 호출 경로 없으면 재료 선택 |

- 예시는 네 재료를 기준으로 실제 검수 Recipe가 있을 때 그 메뉴명으로 표시한다. 검수 전에는 위처럼 방식 설명만 사용하고 임의 요리를 추천 결과로 만들지 않는다.
- 상태: 처음은 임시 1명·재료 최대 활용형 선택 **(가정)**. 불러오는 중은 기존 설정 복원만 표시, 예시 데이터가 필요하면 예시 영역에만 로딩. 정상은 저장값 선택 상태. 오류는 저장 실패 문구와 재시도 가능한 저장 버튼, 메모리 설정으로 계속 사용 가능; 예시 로딩 실패가 설정 저장을 막지 않는다.
- 광고 개수: 0개.
- PC에서 달라지는 점: 최대 폭 640px 한 열 유지. 인원 4개 가로 배치, 방식은 세로 배치 유지.
- 연결된 plan.md 작업 번호: 2-1, 2-2, 2-3, 2-4, 6-2.

### 3. 재료 선택 — `/ingredients.html`

- 목적: 관심 식재료를 표준 식재료 목록에서 복수 선택한다.
- 배치:

```text
┌────────────────────────┐
│ 공통 상단               │
├────────────────────────┤
│ 재료 선택               │
│ 관심 식재료를 골라 주세요.│
│ [재료명 검색____________]│
│ ┌자동완성 결과────────┐ │
│ │ 계란                │ │
│ └─────────────────────┘ │
│ 선택한 재료 2개          │
│ [팽이버섯 ×] [양파 ×]   │
│ 채소·버섯               │
│ [팽이버섯] [양파] [감자]│
│ 육류·해산물             │
│ [오징어]                │
│ 두부·계란·기타           │
│ …등록된 빠른 선택 버튼  │
│ 양념·조미료             │
│ …등록된 빠른 선택 버튼  │
│ [메뉴 추천]             │
│ 공통 바닥글             │
└────────────────────────┘
```

| 요소 | 내용(실제 문구 예시) | 누르면 일어나는 일 |
|---|---|---|
| 검색 입력 | 라벨 `재료명 검색`, placeholder `예: 오징어, 양파` | Ingredient.name·aliases 검색; 입력만으로 등록 안 됨 |
| 자동완성 | `계란` | Ingredient.id 선택, 입력 비우기; 이미 선택된 항목은 `선택됨` 표시·중복 추가 안 함 |
| 선택한 재료 | `팽이버섯 ×`, `양파 ×` | 삭제 이름 읽기 `양파 선택 해제`; 관심 ID만 제거 |
| 카테고리 빠른 선택 | 표준 이름 버튼 | isQuickPick인 재료만 표시, 선택/해제 토글 |
| 주요 버튼 | `메뉴 추천` | 메뉴 추천 이동; 0개일 때도 이동 가능하고 해당 화면에서 안내 |

- 카테고리는 장보기 목록의 네 이름·순서 사용, 항목 없는 카테고리는 생략 **(가정)**. 양념 선택은 가능하되 `양념·조미료는 추천 점수에서 제외하고 장보기 목록에는 포함해요.` 표시. 등록 안 된 이름은 `등록된 재료가 없어요. 다른 이름으로 검색해 주세요.`만 표시하며 임의 등록 기능 없음.
- 상태: 처음은 선택 0개·검색·빠른 버튼. 불러오는 중은 재료 영역에 상태 문구, 로딩 중 버튼은 비활성. 정상은 선택 개수·버튼 체크·자동완성. 오류는 `재료를 불러오지 못했어요.`와 다시 시도; 기존 선택 및 메뉴는 삭제하지 않는다. 검색 결과 없음은 입력 아래 안내.
- 광고 개수: 0개.
- PC에서 달라지는 점: 좌측 검색·선택 재료 320px, 우측 카테고리 `minmax(0,1fr)`, gap 24px. 문서 순서는 휴대폰과 같고 고정 영역 없음.
- 연결된 plan.md 작업 번호: 2-1, 3-1, 3-2, 3-5, 6-1, 7-2.

### 4. 메뉴 추천 — `/recipes.html`

- 목적: 추천 방식을 비교하고 메뉴를 담으며 조리 횟수를 정한다.
- 배치:

```text
┌────────────────────────┐
│ 공통 상단               │
├────────────────────────┤
│ 메뉴 추천               │
│ 기본 식사 인원: 1명 [기본 설정]│
│ 선택 메뉴               │
│ [오징어볶음 · 1회]      │
│ 펼친 경우 [−] 1회 [+] [삭제]│
│ 관심 식재료: 오징어·양파 │
│ [재료 선택]             │
│ [재료 최대 활용형]      │
│ [추가 재료 최소형]      │
│ [여러 끼 식단형]        │
│ 현재 방식 설명          │
│ ┌추천 카드────────────┐ │
│ │ 검수된 메뉴명       │ │
│ │ 조리 시간·조리 유형 │ │
│ │ 추천 이유           │ │
│ │ [담기]              │ │
│ └─────────────────────┘ │
│ …최초 최대 8개          │
│ [더 보기]               │
│ [장보기 목록]           │
│ [광고]                  │
│ 공통 바닥글             │
└────────────────────────┘
```

| 요소 | 내용(실제 문구 예시) | 누르면 일어나는 일 |
|---|---|---|
| 선택 메뉴 | `오징어볶음 · 1회` | 공통 인라인 횟수 편집, 삭제 시 추천 후보 재계산 |
| 관심 식재료·수정 | `오징어·양파`, `재료 선택` | 재료 선택 이동, 기존 메뉴 유지 |
| 세 탭 | 재료 최대 활용형 / 추가 재료 최소형 / 여러 끼 식단형 | activeRecommendationMode 변경, 처음 최대 8개로 복귀 |
| 추천 카드 | Recipe.name, cookMinutes가 있으면 `20분`, cookingType | 카드 자체 클릭 없음; 상세 화면 만들지 않음 |
| 추천 이유 | `관심 식재료 오징어·양파를 활용해요.` / `추가 일반 재료 2종이 필요해요.` / `선택 메뉴에 없는 조리 유형이에요.` | 실제 계산 결과인 이유만 표시, 양념 제외 |
| 담기 | `담기` | selectedRecipes에 times=1로 1개 추가; 해당 후보 제외·추천 재계산; `메뉴를 담았어요.` 알림 |
| 더 보기 | `더 보기` | 다음 최대 8개 추가, 끝이면 숨김 |
| 다음 행동 | `장보기 목록` | 목록 이동, 선택 메뉴 없어도 빈 상태로 접근 가능 |

- 기본 추천 방식이 세 가지 모두 비교이면 재료 최대 활용형 탭으로 시작 **(가정)**; 유효한 ShoppingDraft.activeRecommendationMode가 있으면 그 탭 복원. 세 탭을 항상 제공한다. 담기·삭제·재료·모드 변경 시 첫 8개로 돌아가되 상단 선택 메뉴와 횟수는 유지한다. 갱신 후 포커스가 사라지면 추천 영역 제목으로 보내고 결과 개수를 알린다.
- 이미지는 MVP에서 생략 **(가정)**. 이미지가 없다고 빈 이미지 틀을 만들지 않는다. Recipe.sourceNote는 검수 데이터이며 원문 전문·유튜브 링크 UI를 추가하지 않는다.
- 상태: 처음(관심 재료 없음)은 선택 메뉴를 유지하고 `관심 식재료를 먼저 선택해 주세요.` + 재료 선택. 불러오는 중은 선택 메뉴 유지·후보 영역 상태 문구. 정상은 실제 후보 최대 8개·현재 방식 설명. 후보 0개는 `현재 조건에 맞는 추천 메뉴가 없어요.`와 재료 선택 링크(모두 담은 경우 `추천 메뉴를 모두 담았어요.`). 오류는 후보 영역에 재시도, 선택 메뉴·장보기 목록 링크 유지.
- 광고 개수: 승인 전 0개 / 승인 후 목록·CTA 아래 최대 1개. 후보 없음·오류 상태에는 숨김 **(가정)**.

- 연결된 plan.md 작업 번호: 3-3, 3-4, 3-5, 5-1, 5-2, 5-3, 5-4, 5-5, 5-6, 5-7, 6-1.

- 목적: 메뉴별 필요량을 합산한 재료를 확인·구매 체크·복사한다.

```text
┌────────────────────────┐
│ 공통 상단               │
├────────────────────────┤

│ 선택 메뉴               │
│ [오징어볶음 · 1회]      │
│ 펼친 경우 [−] 1회 [+] [삭제]│
│ [목록 복사]             │
│ 채소·버섯               │
│ □ 양파            총량  │
│   오징어볶음 · 메뉴별 수량│
│   오징어찌개 · 메뉴별 수량│
```

| 요소 | 내용(실제 문구 예시) | 누르면 일어나는 일 |
|---|---|---|
| 선택 메뉴 | 메뉴명·조리 횟수 | 횟수·삭제 인라인 편집, 합산 즉시 재계산 |
| 목록 복사 | `목록 복사` | 카테고리·재료명·총량을 텍스트 복사; 성공 알림 `목록을 복사했어요.` |
| 카테고리 제목 | 채소·버섯 / 육류·해산물 / 두부·계란·기타 / 양념·조미료 | 없음; 빈 카테고리 생략 **(가정)** |
| 재료 체크 | `양파` + 계산된 총량 | checkedIngredientIds 토글; 체크 후 행·수량·사용 메뉴 유지 |
| 사용 메뉴 | `오징어볶음 · {계산된 수량과 원문 단위}` | 없음, 처음부터 펼쳐 표시 |
| 이동 링크 | `메뉴 추천`, `재료 선택` | 기존 작업을 유지하며 해당 화면 이동 |
| 초기화 | `새 장보기 시작` | 현재 화면 위 확인창 표시 |

- `Ingredient.id`·같은 단위끼리만 합산. 다른 단위는 `1.5마리 + 200g`처럼 나란히 표시하고 모바일에서는 줄바꿈 허용. 일부 수량이 null이면 알려진 총량에 `+ 수량 미기재`도 함께 표시하며 해당 메뉴 아래에도 `수량 미기재`를 남긴다. 양념도 표시한다. 수량 직접 보정은 넣지 않는다.
- 복사에는 체크 여부도 `[ ]`·`[x]`로 포함 **(가정)**, 단위·수량 미기재 유지. 복사 API 실패 시 같은 영역에 readonly textarea와 `복사하지 못했어요. 아래 목록을 선택해 복사해 주세요.` 표시. 별도 화면·파일 다운로드 없음.
- 확인창: 제목 `새 장보기 시작`, 본문 `현재 관심 식재료, 선택 메뉴, 조리 횟수, 구매 체크를 지우고 새 장보기를 시작할까요? 기본 설정은 유지돼요.`, `[취소] [새 장보기 시작]`. 확인 시 ShoppingDraft만 초기화, 현재 추천 방식은 유지된 기본 추천 방식에서 다시 시작 **(가정)**. 저장 실패 시 재방문에 이전 작업이 남을 수 있음을 알린다.
- 상태: 처음(선택 메뉴 없음)은 `선택한 메뉴가 없어요.` + 메뉴 추천, 복사 비활성·광고 숨김. 불러오는 중은 선택 메뉴 복원/계산 영역 상태 문구. 정상은 합산·사용 메뉴·체크 표시. 오류는 재료/레시피 데이터 로딩 오류 + 다시 시도; 불명확한 총량을 0으로 표시하지 않으며 복사 비활성. 저장 실패는 공통 경고를 띄우고 현재 화면 조작 유지.
- 광고 개수: 승인 전 0개 / 승인 후 정상 목록 하단 최대 1개.
- PC에서 달라지는 점: 목록 한 열 유지, 사용 메뉴 들여쓰기 32px. 재료명과 총량을 양 끝 정렬하고 긴 수량은 줄바꿈. 복사 버튼은 제목 아래 오른쪽 정렬.
