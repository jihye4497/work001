# 오늘 뭐 담지?

HTML5·CSS3·JavaScript ES Modules로 만든 모바일 우선 장보기 웹사이트입니다. 빌드·패키지 설치·API 키가 필요하지 않습니다.

## 로컬 실행

프로젝트 루트에서 Python 3가 설치된 환경 기준으로 실행합니다.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. 파일을 더블클릭하는 `file://` 방식은 ES Modules와 JSON 로딩을 지원하지 않습니다. 서버를 종료하려면 실행한 터미널에서 Ctrl+C를 누릅니다.

## 자동 확인

Node.js 22.18 이상(현재 개발 환경: 26.13.0)의 기본 테스트 실행기를 사용하며 라이브러리는 설치하지 않습니다.

```powershell
node --test tests/core.test.mjs tests/import-mfds.test.mjs
git diff --check
```

테스트는 데이터 검증, 표준 재료 검색, 인원·횟수 계산, 같은 단위 합산, 다른 단위 분리, 수량 미기재, 양념 분류, 추천 세 방식과 동점, 8개씩 표시, 저장 복원·오류·초기화를 확인합니다. 화면 전체의 브라우저 검증을 대신하지 않습니다.

## 직접 확인

1. 기본 설정에서 인원·방식을 고른 뒤 저장합니다.
2. 재료 선택에서 양파·감자를 고르고 메뉴 추천으로 이동합니다.
3. 메뉴 두 개를 담고 선택 메뉴를 눌러 조리 횟수를 바꿉니다.
4. 재료 선택으로 돌아가 오징어를 추가합니다. 기존 메뉴·횟수가 남는지 확인합니다.
5. 메뉴 추천에서 세 방식 탭을 바꿔 본 뒤 장보기 목록으로 갑니다.
6. 사용 메뉴·총량을 확인하고 구매 체크·목록 복사를 사용합니다.
7. 새로고침·화면 왕복 후 내용이 남는지 확인합니다.
8. 새 장보기 시작에서 취소하면 유지되고 확인하면 현재 작업만 지워지는지 확인합니다.
9. 360px·768px·1280px에서 가로 스크롤, 키보드 조작, 버튼 가림을 확인합니다.

## 초기 데이터와 검수 범위

현재 메뉴는 453개입니다. 기존 8개와 식품안전나라의 명시 인분 59개, 사용자 승인에 따른 1인분 추정 386개로 구성됩니다. 이번 확장에서는 명시 인분 36개와 추정 384개를 추가했습니다. `data/recipes.json`의 `sourceNote`에 출처와 검수 근거를 기록했습니다.

출처: [테팔 터보퀴진 공식 레시피북](https://dam.groupeseb.com/m/72b0457b12251391/original/TEFAL_CY7551KR_Recipe-Book.pdf).
재료량·원문 단위·기준 인분을 대조했으며 사진·조리 설명은 복제하지 않았습니다. 조리시간은 기기 전용이므로 일반 시간으로 표시하지 않습니다. `깐마늘`과 `다진 마늘`은 다른 표준 ID를 사용하며 가공 상태를 치환하지 않습니다.

표준 재료 ID 기준으로 양파 메뉴 170개, 팽이버섯 15개, 오징어 12개, 감자 33개, 계란 55개입니다. 다진 재료나 특정 부위처럼 별도 ID인 재료는 이 수에 합치지 않습니다. 관련 재료가 없는 후보를 생성하지 않으며 모든 재료에서 8개를 보장하지는 않습니다. 이미 담은 메뉴는 추천에서 제외하므로 남은 후보 수는 줄어듭니다.

## 식품안전나라 수집·검사

출처는 식품의약품안전처 `COOKRCP01`입니다. [공식 메타정보](https://www.data.go.kr/catalog/15060073/openapi.json)의 이용허락범위는 제한 없음으로 표시되어 있습니다. 사진·조리 설명·영양 주장은 가져오지 않습니다.

2026-11-10 인증키로 전체 1,156건 수집을 완료했습니다. 고유 원본 ID 1,156개, 띄어쓰기·문장부호 정리 후 고유 메뉴명 1,142개, 같은 이름 후보 13그룹(27개 원본)입니다. 이름이 같다고 재료·분량까지 같은 것은 아니므로 후보를 무조건 삭제하지 않습니다. 대괄호 없는 `2인분 기준`·`재료 1인분`도 인식해 인분 명시 62건 중 59건을 반영했습니다. 보완 원문 2건을 포함한 전체 1,158건 중 445건을 반영하고 713건은 보류했습니다. 보류 중 3건은 원본 재료정보가 비어 있습니다.

- `data/source/mfds-response.json`: 전체1,156건의 원본 응답입니다. 필요한 메뉴·재료 필드만 보관하며 인증키는 없습니다.
- `data/source/mfds-page2.json`: 다른 범위에서도 같은5건이 반환된 확인용 응답입니다.
- `data/source/mfds-supplement.json`: 현재 API 목록에는 없고 공식 안내 페이지 SAMPLE 목록에 남아 있는 `칼륨 듬뿍 고구마죽`·`누룽지 두부 계란죽`의 보완 원문2건입니다. API 전체1,156건과 합쳐 검사한 고유 원문은1,158건입니다.
- `data/source/mfds-reviews.json`: 명시적 인분, 원문 재료 구절, 수량·단위와 표준 ID를 대조한 검수 기록입니다.
- `data/source/mfds-import-report.json`: 고유 수집 수·보류 사유·동일 이름 후보·재료별 메뉴 수를 확인합니다.
- `data/source/mfds-expansion-policy.json`: 사용자 승인한 추정 후보 ID·원본 목록 해시·제빵 제외·소스 처리 기준을 보관합니다.
- `data/source/mfds-expansion-report.json`: 이번 추가 420건의 원본 분류와 검토 대상 중 보류 사유를 기록합니다. 제빵·제과 48건은 제외하고, 인분 미명시 절임·반찬 71건은 나중에 별도 구분을 검토할 목록으로 남겼습니다. 이 파일의 보류 목록은 전체 713건 중 이번 검토 범위만 다룹니다.

기존 파일로 검사·반영합니다. 다시 실행해도 같은 메뉴를 추가하지 않습니다.

```powershell
node scripts/import-mfds.mjs
```

추가 검수한22건의 근거 기록은 `scripts/review-mfds.mjs`의 명시적 ID 목록에 한정되어 있습니다. 다른 원본을 자동 승인하지 않습니다. `node scripts/review-mfds.mjs` 실행 후 `node scripts/import-mfds.mjs`로 재검사할 수 있습니다. 분수는 같은 단위의 숫자만 해석하며, 원문에 함께 적힌 g을 사용할 때는 원래 표기를 메모에 남깁니다. Ts·ts·T·t를 서로 환산하지 않습니다.

사용자 승인(2026-11-10)으로 인분 확인을 세 가지로 구분합니다. 명시된 인분은 유지하고, 사전 검토한 후보 중 재료 대조를 통과한 메뉴에만 `servingsStatus: estimated`와 추정 근거를 저장하며, 판단하기 어려운 메뉴는 보류합니다. 열량 수치만으로 인분을 계산하거나 미표기 메뉴 전체를 자동 승인하지 않습니다. `node scripts/review-estimated-servings.mjs`는 최초 보완 메뉴 2건의 검토 기록만 추가합니다. `node scripts/expand-mfds.mjs`는 승인된 목록을 재검사만 하고, `--write`를 붙여야 확장 검수 기록·사이트 데이터·보고서를 저장합니다. 원본 목록 해시가 달라지면 중단하며 기존 메뉴 ID가 사라지는 결과는 저장하지 않습니다.

추정 표시는 추천 카드·선택 메뉴·사용 메뉴·재료 합산·복사에 남습니다. 명시된 인분도 카드·선택 메뉴·사용 메뉴에 `4인분 기준`처럼 표시합니다. 현재 원본의 명시 인분은 1·2·4인분이며, 향후 명시된 6·8인분도 같은 검증 방식으로 유지합니다. 소스는 별도로 인분을 계산하지 않고 원문 재료량을 유지합니다. 치즈리조또의 우유는 원문 `180mg`을 그대로 저장하며 오류 여부를 확정하거나 mL로 바꾸지 않습니다. 범위·복합 표기로 한 숫자를 결정할 수 없는 29개 재료 항목은 원문 메모를 남기고 `수량 미기재`로 표시합니다. 누룽지 두부 계란죽의 물도 수량 미기재입니다. 기본 `node scripts/import-mfds.mjs`는 전체 원문과 보완 원문을 함께 검사합니다.

전체 수집은 [식품안전나라 데이터활용서비스](https://www.foodsafetykorea.go.kr/api/newDatasetDetail.do?svc_no=COOKRCP01)에서 COOKRCP01 이용 신청·인증키 발급 후 가능합니다. 키는 채팅·소스·명령 인자에 붙여 넣지 않습니다. 아래 명령은 입력을 가리고 해당 프로세스에서만 키를 사용합니다. 사이트 실행에는 키가 필요하지 않습니다.

```powershell
$mfdsSecureKey = Read-Host '식품안전나라 인증키' -AsSecureString
$mfdsCredential = [System.Net.NetworkCredential]::new('', $mfdsSecureKey)
$env:MFDS_API_KEY = $mfdsCredential.Password
try { node scripts/import-mfds.mjs --download } finally { Remove-Item Env:MFDS_API_KEY; $mfdsCredential = $null; $mfdsSecureKey = $null }
```

전체를 내려받더라도 모든 메뉴를 자동으로 사이트에 넣지는 않습니다. 검수 기록이 없는 항목은 보류합니다. 승인된 추정 메뉴 외에는 인분을 임의로 추정하지 않습니다. g·mL·숟가락을 변환하지 않고, 원문에 병기된 g 수량은 그 값을 그대로 사용합니다. `약간`은 null로 남깁니다. 원문 해시·인분·수량·단위·누락 재료를 확인하고 기존 이름 중복은 보류합니다. 비슷한 이름의 의미상 중복은 사람이 최종 검수해야 합니다. 원본 ID와 기존 사이트 ID는 유지합니다.

운영자의 최종 데이터·이용조건 검수(계획 2-4·7-3)는 미완료입니다. 원문 오타·메뉴명과 재료 불일치·대량 절임류의 미명시 인분은 최종 검토가 필요합니다. 레시피 수량을 임의로 만들어 보강하지 않습니다.

## 공개 전 남은 작업

- 실제 운영자 정보·문의 연락처·정책 시행일과 최종 문안을 확정합니다. 현재 안내 페이지에는 미정 상태를 명시했습니다.
- Cloudflare Pages 프로젝트와 GitHub 저장소를 사용자가 직접 연결합니다. 정적 사이트로 설정하고 프레임워크는 없음, 빌드 명령은 비움, 출력 디렉터리는 프로젝트 루트로 설정합니다. 실제 설정 UI와 자동 배포 상태를 확인합니다.
- 도메인을 확정한 뒤 `sitemap.xml`에 실제 URL을 추가하고 공개 준비가 끝나면 HTML의 `noindex, nofollow`와 `robots.txt`의 전체 크롤링 차단을 해제합니다. 현재 사이트맵은 빈 상태이며 검색 등록 준비 완료가 아닙니다.
- Cloudflare Pages가 잘못된 주소에 `404.html`을 반환하는지 배포 환경에서 확인합니다.
- Google Fonts 외 분석·광고 스크립트는 없습니다. 개인정보 안내에 실제 호스팅 로그 처리와 도입 도구를 반영합니다.
- AdSense 승인 전에는 광고를 넣지 않습니다. `ads.txt`는 빈 파일이며 가짜 게시자 ID를 넣지 않았습니다.
